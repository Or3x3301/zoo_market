# zoo_market
## 1. Введение и общие положения

- **Наименование проекта:** Федеральная омниканальная PetTech-экосистема (рабочее название).
- **Суть проекта:** Оцифровка существующего розничного бизнеса и создание единой цифровой платформы, объединяющей онлайн-торговлю зоотоварами, маркетплейс сторонних продавцов (заводчиков) и агрегатор бытовых/медицинских услуг для владельцев домашних животных.
- **Бизнес-контекст:** Проект опирается на сильную офлайн-базу — действующую розничную сеть из **20 магазинов в Дальневосточном регионе**, учетную систему **1С** и валидированную базу из **1 500 активных клиентов**. Онлайн-платформа создается для бесшовного объединения каналов продаж и подготовки ИТ-инфраструктуры к масштабированию.
- **Инвестиционный бюджет:** **15 000 000 рублей**, рассчитанный на горизонт планирования **2 года (24 месяца)**.

## 2. Миссия, цели и видение проекта

- **Миссия проекта:** Обеспечить владельцам питомцев единую, удобную и персонализированную точку доступа ко всем необходимым товарам и услугам заботы о животных, минимизируя время на поиск, выбор и покупку.
- **Бизнес-цели:**
    - Краткосрочная (до 3 месяцев): Запуск e-commerce канала продаж и оцифровка текущей розницы на Дальнем Востоке.
    - Долгосрочная (24+ месяца): Выход на рынок Центральной России с масштабируемой ИТ-платформой и распределенными фулфилмент-центрами.
- **Метрики успеха (KPI):** Количество интернет-заказов, доля омниканальных клиентов (покупающих и онлайн, и в магазинах), конверсия поисковой системы, глубина использования профилей питомцев, ROI инвестиций на каждом этапе (Phase).

## 3. Целевая аудитория (ЦА)

- **Профиль покупателя:** Владельцы домашних животных.
- **Сегментация:**
    - _Розничные клиенты (B2C):_ самовывоз и доставка через СДЭК/Boxberry.
    - _Профессиональные сообщества (B2B):_ Верифицированные заводчики и питомники.
    - _Благотворители:_ Пользователи, готовые финансово поддерживать приюты через КСО-модули.
- **Основные боли ЦА:** Сложность подбора правильного корма/лекарств по индивидуальным параметрам питомца; разрозненность сервисов (магазины, клиники, груминг — все в разных местах); отсутствие прозрачных отзывов о ветеринарах и товарах.

## 4. Границы проекта и ключевой функционал

Развитие ИС строится по модели контролируемых фаз (Phased Rollout).

- **Что входит в систему:**
    - _Phase 1 (M3):_ Адаптивный веб-сайт, интеллектуальный поиск (автозаполнение, опечатки, синонимы), UGC (лайки, избранное, отзывы с премодерацией), финтех-модуль (онлайн-оплата, СБП, Яндекс Пэй, фискализация по 54-ФЗ), омниканальная CRM/лояльность (сквозная авторизация по СМС/Flash Call), гео-ритейл (самовывоз из 20 точек и СДЭК/Boxberry).
    - _Phase 2 (M6):_ Мобильное приложение (iOS/Android) с оплатой в 1 клик, личные кабинеты заводчиков, КСО-модуль донатов приютам со сплитованием платежей, AI-рекомендательный движок («С этим товаром покупают», «Похожие товары»).
    - _Phase 3 (M12):_ MedTech-агрегатор (интеграция с МИС ветклиник для онлайн-записи).
    - _Phase 4 (M18):_ Маркетплейс услуг (груминг, передержка) с интеграцией 2ГИС и функционалом «Безопасной сделки» (Escrow).
- **Что НЕ входит в систему на старте:** Собственная курьерская служба автоматизации последней мили (используются внешние API), международные продажи, оптовые закупки B2B-поставщиков (только заводчики).

## 5. Высокоуровневые требования и ограничения

- **Технологические предпочтения:** Рекомендуется использование модульной монолитной архитектуры на базе elysiajs для бэкенда для обеспечения гибкой интеграции AI-компонентов и внешних API с последующим бесшовного выделением отдельных модулей (MedTech, Услуги) в независимые микросервисы на этапах. Фронтенд на SvelteKit (для SEO веб-сайта). Мобильное приложение на кроссплатформенном фреймворке Flutter для оптимизации бюджета.
- **Интеграции:**
    - 1С (двусторонний обмен данными в реальном времени: остатки в 20 точках, цены, выгрузка заказов).
    - Платежный шлюз (эквайринг, СБП, механизмы сплитования платежей и Escrow-счета).
    - Логистические сервисы (СДЭК, Boxberry API).
    - Медицинские информационные системы (МИС) ветклиник.
    - Картографический сервис 2ГИС (Phase 4).
- **Регуляторные ограничения:** Соблюдение законов РФ: 152-ФЗ «О персональных данных», 54-ФЗ «О применении контрольно-кассовой техники» (фискализация через связку платежного шлюза и 1С).

## 6. Профили пользователей ИС (Роли в системе)

- **Внешние пользователи (Клиенты и Партнеры):**
    - _Гость:_ Неавторизованный пользователь. Доступен поиск, просмотр каталога, цен и отзывов.
    - _Покупатель:_ Авторизован по номеру телефона. Доступны: история заказов, баланс лояльности, добавление в Избранное/Лайки, создание профиля питомца, онлайн-оплата и запись к врачам.
    - _Заводчик / Партнер:_ Проверенный контрагент. Имеет доступ в личный кабинет для размещения своих предложений на маркетплейсе.
    - _Исполнитель услуг:_ Специалист (грумер, догситтер), размещающий анкету и принимающий оплату через Escrow.
- **Внутренние пользователи (Персонал):**
    - _Контент-менеджер:_ Модерирует отзывы покупателей (UGC), вручную настраивает статические рекомендации товаров, наполняет каталог.
    - _Оператор/Менеджер по заказам:_ Обрабатывает инциденты, контролирует статусы обмена данными с 1С.
    - _Кладовщик/Сотрудник розничной точки:_ Получает уведомления о бронировании, собирает заказ на полке магазина, подтверждает готовность к выдаче.
    - _Администратор системы:_ Настраивает интеграции, роли сотрудников и права доступа.

## 7. Способы взаимодействия с ИС (Каналы доступа)

- **Веб-сайт (Адаптивный Web):** Основной интерфейс. Доступен с десктопов и смартфонов.
- **Мобильное приложение (iOS/Android):** Запускается на Phase 2. Фокусируется на удержании клиентов, покупках в 1 клик и отправке Push-уведомлений.
- **Панель администрирования:** Веб-интерфейс для управления платформой контент-менеджерами и операторами.
- **POS-терминалы / Кассы розницы:** Интерфейс интеграции кассового ПО с единой базой лояльности ИС для идентификации клиента по номеру телефона при офлайн-покупке.
